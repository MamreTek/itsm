# 架构与后端交接

UI → 统一 API 客户端 → 注入的 Fetch-compatible transport → Mock 路由/校验 → 内存记录。

业务组件不直接导入种子数据。Mock 与 UI 使用同一契约类型，HTTP 状态/响应 envelope 对齐公开文档；Mock 不是可部署的 API 服务。当前 API URL `http://itsm.mock.local` 仅用于构造内存 Request，没有 DNS 或网络请求。

## 实现边界

工单状态、版本检查与 SLA 快照逻辑集中在 Mock 边界，用于流程验证。真正后端应在事务内执行这些检查并持久化。前端的禁用、导航和模拟目录不提供安全控制。本期没有新增菜单、按钮、接口权限，也没有改动其他产品的权限。

目录、人员和策略由各自 API 读取。策略调整只作用于新工单；ticket.sla 保存创建时快照，避免历史时限随模板修改。页面不显示虚构趋势或历史达标率。

`src/shared/api/sla.ts` 提供 UI 与 Mock 共用的 SLA/视图判定。列表返回单次 evaluatedAt，保证该次队列行、活跃超时视图与全量计数使用同一时刻；尚未履约与历史超时分别展示。人员筛选与视图由 API 执行，UI 不在分页后自行过滤。

批量分派使用独立端点，先做整批结构校验，再逐项执行与单条分派相同的版本/状态检查。Modal 保存打开时的本页工单版本快照；收到 200 后展示逐条结果，刷新队列并清空勾选。请求级失败保留原输入，不自动重试；部分失败需要基于最新列表重新选择。该 Mock 同步内存写入不具备真实后端事务、持久化或断线幂等保证。

`useResource` 管理加载、失败和重试，忽略卸载后及过期请求结果。写操作防重复点击，不自动重试；API 错误包含请求标识，409 明确要求刷新，不静默覆盖新版本。模拟数据仅活在内存中，刷新/重置即恢复初始数据。

## 流程定义与模拟编排

`src/features/workflows` 提供设计器、SVG/DOM 画布与模拟面板。`src/shared/api/workflows.ts` 是契约，`src/shared/workflow/model.ts` 是纯图校验；`src/mocks/workflows.ts` 负责草稿版本、冻结实例、分支选择与逐步模拟，仍由既有 transport 提供统一 envelope 和故障注入。没有引入第三方图引擎、Ferry 源码或服务。

`WorkflowSessionProvider` 在路由页面之外保留流程编辑状态，避免 Designer 卸载后丢失未保存图和最近等待实例。它仅保存页面内的 React 状态，不调用写 API，也不使用浏览器持久存储；提交状态和错误一并保留。全局 Mock 重置通过原有 revision key 同时重建这个容器，防止旧草稿或实例残留。关闭/刷新提示由容器处理，因此切换到其他模块后仍能提示未保存改动。此编辑状态容器与身份认证会话无关。

保存允许语义未完成的草稿，结构错误请求不写入。只有无环且完整的已保存图可模拟。启动时复制流程与输入，等待节点动作在实例副本上校验、推进后才提交；后续定义编辑不改变实例。条件只有枚举等值比较，不执行脚本；节点负责人是虚构目录引用，不是身份或权限。流程模拟与原工单状态机相互独立，重置同时恢复两者。

真实后端需要重新设计持久化版本、并发比较、未知写入结果查询、身份和资源授权；当前内存图校验与同步模拟不能替代生产工作流引擎。详细语义见 [工作流 API](workflow-api.md)，参考来源与访问限制见 [Ferry 核验记录](workflow-reference.md)。

## 离线预览构建

`scripts/build-offline.mjs` 复用同一 `src/app/main.tsx` 和 Vite/React 编译链，以 IIFE 格式生成一个脚本，将 CSS 内联到 `offline/index.html`。不依赖 CDN、同级资源文件、开发服务器或跨文件访问例外；构建发现额外脚本/资源依赖时直接失败。生成文件被 Git 忽略，不携带本机路径或源码映射。源码 HTML 在 file:// 下显示打开指引，不再尝试请求 TSX。

离线浏览器回归将生成文件复制到带空格与中文的空目录，关闭网络后验证核心工单流程、刷新重置，以及没有控制台错误和外部请求。普通 HTTP 开发/构建模式继续单独回归。

`scripts/serve-preview.mjs` 可将构建好的单文件用于本机展示，默认仅监听回环地址，可显式增加一个已分配给本机的私有 IPv4。服务不提供源码目录或真实 API，不做路由转发，不改网络配置，停止后无持久服务。Mock 标识符在普通局域网 HTTP 缺少 randomUUID 时使用 getRandomValues 生成不透明随机 ID，仅服务于模拟记录，不用于会话或授权。

## 后续真实服务

1. 冻结当前契约的业务版本，明确工作日历、服务分类与真实身份模型。
2. 建立 Go/go-zero API、存储和迁移；用相同契约案例验证响应、状态机、SLA 快照、并发及失败原子性。
3. 在适配层注入指向受控服务的 transport，映射路径；保留业务页面调用接口。当前没有可误接生产的环境开关。
4. 完成登录、后端授权、隔离、安全审计、输入约束、CSRF 等正式设计与验收。处理超时导致的未知写入结果和幂等重试。不得仅因 Mock 测试通过就对外使用。
5. 在独立授权的测试环境验证；生产发布另行授权。

没有复制 OpsAtlas 私有代码、主题源文件或客户数据；该工程仅提供了既有 ITSM 页面范围的流程参考。本仓库所有业务实现独立编写。外部需求记录不纳入源码库；通过 REQ-001 和公开 Issue 关联。
