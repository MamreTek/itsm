## 采用的产品思路

将“流程配置”和“流程执行”区分为草稿与冻结版本，先定义节点、出口和人员，再用虚构请求检查实际路径。条件采用明确的枚举等值比较；审批与处理分别等待模拟操作，执行记录与图上的已走路径保持对应。

| Ferry 所描述能力 | ITSM 本期原型 |
| --- | --- |
| 自定义流程、条件跳转 | 开始、条件、审批、处理、结束节点；可移动画布与明确的连线表单；结构和业务校验 |
| 串行与并行处理 | 串行与排他条件分支；并行会签、并行网关留待需求确认 |
| 灵活处理人 | 使用已有虚构人员目录；不推导真实组织关系或授权 |
| 模板、任务钩子 | 提供独立编写的流程示例；没有动态表单设计器、脚本、通知、Webhook、作业或外部调用 |
| 流程处理 | 已保存版本的内存模拟；审批通过/拒绝、处理完成、输入校验、版本冲突、执行路径和快照 |

UI 沿用 [Ant Design Pro 参考说明](ui-reference.md) 的导航、标题、工具栏、卡片与表单模式。流程图是必要的业务专用视图，使用本地 SVG 连线和 DOM 节点；窄屏在画布内滚动，选中节点时在画布内定位，支持拖动和键盘方向键。没有转用 Ferry 的 Vue/Element UI 技术栈。

## 边界

此功能验证产品交互和 API 契约，不构成真实企业审批引擎、BPMN 兼容性、持久调度、身份授权或安全审计。流程图限 30 节点、80 连线、无环；不接受可执行表达式。业务工单与模拟流程实例保持独立，模拟动作不会改变原工单。
